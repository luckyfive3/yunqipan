# 云栖盘 · 性能优化与功能扩展路线

## 1. 性能优化方向

### 1.1 下载链路（按收益排序）
1. **对象存储直出**：分享/公开资源改用 MinIO 预签名 URL，客户端直连对象存储下载——网关出口不再是瓶颈，带宽利用率与延迟同时改善（需在鉴权与直链之间加短时签名，已预留 preview-token 同类机制）。
2. **HTTP/2 → QUIC/HTTP3**：多线程下载从 N 条 TCP 连接收敛为一条多路复用连接（或 UDP），降低弱网下的队头阻塞与握手开销；自研内核的连接抽象已为此预留。
3. **动态线程数**：由“固定线程 + 块内再分块”升级为按 `RTT × 带宽` 的 BDP 模型实时增减线程数（当前实现是块级自适应，下一步做线程级）。
4. **服务端零拷贝**：`io.Copy` 已够用；进一步可走 `sendfile`/`splice`（Linux）省一次用户态拷贝。
5. **CDN / 边缘缓存**：热门分享与公共资源上 CDN，回源保持签名鉴权。

### 1.2 上传链路
1. **并发分块**：当前顺序传块（1 个块在途），升级为 2~4 块流水线，低延迟高带宽场景上传吞吐可翻倍。
2. **秒传**：`init` 时带 sha256，命中已有对象则直接建元数据（配合全局去重表 `dedup(sha256 → object_key)`，多人传同一文件只存一份）。
3. **客户端压缩**：对高压缩比类型（文本/日志）可选 gzip 前处理（需与 E2E 加密解耦，加密优先）。

### 1.3 服务端
1. **元数据读写分离**：目录列表/树接口走只读副本。
2. **列表缓存**：Redis 缓存目录列表（变更时按 user+parent 失效），千级文件目录秒开。
3. **配额预扣**：init 预占、complete 结算的乐观配额已在设计中；多实例时改为 Redis 计数器 + PG 定期对账。
4. **连接池与限流**：PG 连接池调优；按用户级令牌桶限流下载，防单用户打满。

### 1.4 客户端
1. **渲染层虚拟列表**：万级文件目录只渲染可视区。
2. **缩略图/元数据本地库**：SQLite（better-sqlite3）缓存目录树与缩略图，减少启动后的首屏请求。
3. **原生下载内核提速**：连接池复用（同主机 keep-alive Agent）、写盘合并（16 MiB 聚合写，减少随机写放大）。
4. **打包体积**：评估 Tauri 迁移，安装包从 ~80 MB 降到 ~10 MB。

## 2. 功能扩展方向

### 2.1 文件能力
- 回收站（软删除 + 定时清理）、文件版本历史（MinIO 版本控制 + 元数据版本表）
- 在线 Office 协作（对接 OnlyOffice/Docs 引擎）、图片缩略图服务（MinIO 事件 → 缩略图函数）
- 全文检索（PG tsvector 或 Meilisearch）、OCR/音视频转码（异步任务队列）

### 2.2 分享与协作
- 团队空间 / 群组共享目录、细粒度权限（只读/可编辑/可管理，ACL 表）
- 分享统计（访问日志、下载明细）、举报与合规审核流
- 外链 + E2E 协作：用收件人公钥做信封加密（口令 → 非对称信封），加密文件也可安全分享

### 2.3 同步增强
- 冲突合并（文档类三方合并）、实时推送（WebSocket/SSE，替换轮询，降低空转带宽）
- 多设备同步状态中心、选择性同步（子目录勾选）、文件锁

### 2.4 平台与生态
- WebDAV 挂载（第三方工具直连）、移动端（React Native/Flutter 复用 API）
- CLI 工具、开放 API Key + OAuth2（开发者生态）
- 审计日志、操作留痕、等保合规项（对接企业统一认证 SSO/LDAP）

### 2.5 合规与安全
- 病毒扫描（上传后异步 ClamAV）、敏感内容识别
- 密钥轮换（JWT/预览签名 secret 热更）、登录二次验证（TOTP）
- 平台解析适配器的合规审查流程：每个适配器独立评审、独立开关、独立日志，默认关闭

## 3. 架构演进终态

```
多接入端(桌面/移动/Web/WebDAV/CLI)
        │ HTTPS/QUIC
多实例 API 网关(Go, 水平扩展) ── Redis 会话/缓存 ── PostgreSQL(主从/Citus)
        │ S3 API
MinIO 集群(纠删码) ── 事件流 ── 异步任务(缩略图/转码/杀毒/审计)
        │
CDN/预签名直出(公开分享)
```
